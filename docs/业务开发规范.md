# 云枢 Axis · 业务开发规范

> 版本：1.0  
> 适用范围：`Axis.Host.Api` / `Axis.Application` / `Axis.Domain` / `Axis.Domain.Data` / `Axis.Infrastructure.Data`  
> 目标：统一分层边界、注释、拆分、校验、映射与 FastEndpoints 用法，避免业务代码「揉在一起」。

---

## 1. 分层与依赖

### 1.1 分层职责

| 层 | 项目 | 允许做什么 | 禁止做什么 |
|---|---|---|---|
| 宿主 / API | `Axis.Host.Api` | 路由、权限元数据、Cookie/HTTP 细节、调用 AppService、绑定 Validator | 写业务规则、拼 SqlSugar、直接操作实体持久化 |
| 应用 | `Axis.Application` | 用例编排、业务规则、事务意图、DTO 进出、调用仓储 / `IMapper` | 依赖 `HttpContext`（除极少数认证场景）、在 Endpoint 外写路由 |
| 领域 | `Axis.Domain` | 实体、枚举、领域常量、种子数据 | 引用 Host、写 SQL、依赖具体 ORM API（目标态） |
| 数据契约 | `Axis.Domain.Data` | 按业务域组织：`{Module}/Repository/`、`{Module}/Cache/` | 实现细节、SqlSugar |
| 数据实现 | `Axis.Infrastructure.Data` | 与 Domain.Data 同构：`{Module}/Repository/`、`{Module}/Cache/` | 业务决策（该不该删、权限判断） |
| 基础设施 | `Axis.Infrastructure` | 框架横切（FE 基类、UoW、EasyCaching、异常、Mapster 注册入口） | 具体业务模块用例；实现领域端口 |

### 1.2 依赖方向（强制）

```
Host.Api → Application → Domain.Data → Domain
    │                         ↓
    └→ Infrastructure.Data → Infrastructure
```

- Application **显式项目引用**只需 `Domain.Data`；`Domain` / `Infrastructure` 由其传递引用带入（可直接使用实体、异常、UoW、`ICacheService` 等）。
- Application **不得**引用 `Infrastructure.Data`（只面对仓储/缓存接口，不碰实现）。
- Host（组合根）**必须**引用 `Infrastructure.Data`，保证实现程序集进入输出目录，供 DI 扫描注册。
- Application **不应**为了图省事直接注入 `ISqlSugarClient` 写大段查询（见 §5、§6）。
- `Axis.Infrastructure` 是最底层框架，**不得**依赖 `Domain.Data`；领域缓存实现放在 `Infrastructure.Data`。
- Domain **目标态**不应依赖 Infrastructure；历史包袱（`BaseEntity` / `IRepository` 位置）单独治理，新代码不要继续加深反向依赖。
- 跨模块启动任务放 `Host.Api/HostedServices`，经 `AddAxisHostedServices()` 统一注册。

### 1.3 模块边界（强制）

- 按业务模块竖切：`Author`、`System/User`、`System/Role`、`System/Org` …
- **禁止跨模块挂载能力**：例如机构树必须在 `Org` 模块，不得挂在 `UserAppService`。
- 模块间协作：通过对方的 `IXxxAppService` 或共享只读 Query 服务，禁止直接操作对方实体仓储「抄近路」完成完整用例（除非是明确的领域共享表读取）。

## 2. 模块目录骨架（强制模板）

每个业务模块必须长成同一形状。以 `Role` 为例：

```text
src/Axis.Application/System/Role/
├── Dto/                              # ★ 所有入参/出参必须单独文件，禁止塞进 Service
│   ├── RolePageQuery.cs
│   ├── RoleDto.cs
│   ├── SaveRoleInput.cs
│   ├── GrantRoleMenusInput.cs
│   └── RoleIdRequest.cs              # 仅含 Id 的路径/体参也放 Dto（或 Host 模块 Requests/，见 §2.3）
├── Validators/
│   ├── SaveRoleInputValidator.cs
│   └── GrantRoleMenusInputValidator.cs
├── Mappings/                         # 按需
│   └── RoleMappingRegister.cs
├── IRoleAppService.cs                # ★ 接口单独文件，禁止与实现同文件
└── RoleAppService.cs                 # ★ 仅实现，禁止内嵌 DTO / 接口定义

src/Axis.Domain.Data/
└── System/                             # ★ 先按业务域，再按端口类型
    ├── Repository/
    │   └── ISysRoleRepository.cs       # 有复杂查询时才新增；否则用 IRepository<SysRole>
    └── Cache/
        ├── ISysDictCache.cs            # 领域缓存端口（业务只依赖接口）
        └── ISysConfigCache.cs

src/Axis.Infrastructure.Data/
└── System/
    ├── Repository/
    │   └── SysRoleRepository.cs
    └── Cache/
        ├── SysDictCache.cs
        └── SysConfigCache.cs

src/Axis.Host.Api/
├── HostedServices/                   # 跨模块启动任务（预热等）
└── SystemEndpoints/Role/
    ├── PageRolesEndpoint.cs          # ★ 一文件只放一个 Endpoint 类
    ├── CreateRoleEndpoint.cs
    ├── UpdateRoleEndpoint.cs
    ├── DeleteRoleEndpoint.cs
    ├── GetRoleMenusEndpoint.cs
    └── GrantRoleMenusEndpoint.cs
```


### 2.1 强制拆分（不可妥协）

| 类型 | 存放规则 | 禁止 |
|---|---|---|
| DTO / Query / Input | 一律 `Dto/` 下**一类型一文件** | 写在 `*AppService.cs` 顶部或同文件底部 |
| 应用服务接口 | `IXxxAppService.cs` **独立文件** | 与 `XxxAppService` 同文件 |
| 应用服务实现 | `XxxAppService.cs` **仅实现类** | 内嵌 class/record 定义 DTO、接口 |
| Endpoint | `*Endpoint.cs` **一文件一个 Endpoint 类** | `RoleEndpoints.cs` 里堆多个 Endpoint |
| Validator | `Validators/` 一校验器一文件 | 写在 Endpoint 或 DTO 文件内 |

### 2.2 命名约定

| 类型 | 命名 | 说明 |
|---|---|---|
| 分页查询 | `XxxPageQuery` | 含 `Page` / `PageSize` / 筛选字段 |
| 列表查询 | `XxxListQuery` | 不分页 |
| 详情/列表出参 | `XxxDto` | 不直接返回实体 |
| 新增专用 | `CreateXxxInput` | 与更新字段差异大时使用 |
| 更新专用 | `UpdateXxxInput` | 同上 |
| 新增更新共用 | `SaveXxxInput` | 字段基本一致时优先 |
| 特殊命令 | `动词 + 名词 + Input` | 如 `GrantRoleMenusInput`、`ResetPasswordInput` |
| 应用服务 | `IXxxAppService` / `XxxAppService` | 接口与实现分文件 |
| 端点 | `动词 + 名词 + Endpoint` | 文件名与类名一致，如 `CreateRoleEndpoint.cs` |
| 校验器 | `XxxValidator` | 对应一个 Request/Input |
| 映射注册 | `XxxMappingRegister` | 实现 `IRegister` |

**全仓锁定：**

- 输入模型二选一策略：字段差异小用 `Save*Input`；差异大用 `Create*` + `Update*`。同一模块内不要混用两套。
- DTO / Input / Query 一律 `sealed class`（或 `sealed record`）。
- 前端路径与后端模块名对齐：`position` ↔ `Position`（避免 `pos` / `Position` 混用）。

### 2.3 Endpoint 文件风格（全仓统一）

**选定：一个文件只放一个 Endpoint 类；文件名 = 类名。**

- ✅ `SystemEndpoints/Role/CreateRoleEndpoint.cs` → `sealed class CreateRoleEndpoint`
- ✅ `SystemEndpoints/User/PageUsersEndpoint.cs` → 与 User 模块现有风格一致，作为标准样板
- ❌ `RoleEndpoints.cs` / `DictEndpoints.cs` / `OrgManagementEndpoints.cs` 等多类同文件（存量必须拆开）
- ❌ 在 Endpoint 文件内再定义 Request/DTO（应放到 Application `Dto/`；若仅 Host 使用的薄请求模型，可放同模块 `Requests/XxxIdRequest.cs`，仍须独立文件）
- 同一模块的 Endpoint 放在同一文件夹（如 `SystemEndpoints/Role/`），用文件夹聚合，不用单文件聚合。

### 2.4 字典与枚举选型（强制）

业务里出现「有限选项」时，**先判断能不能走系统字典**；不能走字典的，一律用 **`int` 底层的 C# 枚举**（`enum : int` 或默认 int）。禁止裸 `int` / 魔法数字 / 随意字符串散落在业务代码里。

#### 决策表

| 问自己 | 选字典（`SysDictType` / `SysDictData`） | 选枚举（`Axis.Domain.Enums`） |
|---|---|---|
| 运营/管理员能否在后台增删改选项且**不发版**？ | ✅ 是 | ❌ |
| 选项是否仅影响展示文案、下拉、标签颜色？ | ✅ 优先字典 | — |
| 代码是否按该值做分支（`if` / `switch` / 权限 / 过滤策略）？ | ❌ | ✅ 必须枚举 |
| 缺少某个值会导致程序错误或安全问题？ | ❌ | ✅ 必须枚举 |
| 是否框架/协议级类型（菜单类型、数据范围、租户隔离方式）？ | ❌ | ✅ 必须枚举 |

#### 状态与选项三档选型（必须）

| 档位 | 何时用 | 落库类型 | 说明 |
|---|---|---|---|
| **系统字典** | 业务状态、运营可配、需前端文案/颜色/扩展 | `string`（字典 Value） | **优先**；存有语义编码如 `InProcess` / `Finished`，禁止无意义数字塞进字典 |
| **int 枚举** | 代码强分支、框架/协议级、不可后台乱改 | 枚举（底层 int） | 见 §11；如 `MenuTypeEnum`、`DataScopeEnum` |
| **裸 int + 注释** | 仅 0/1/2 等固定少量、无需配置扩展、无需前端可配文案 | `int` | 实体属性注释**逐值写清**（如 `0待开工 1进行中 2已完工`）；判断用常量，禁魔法数 |

**业务状态优先走字典：** 新增状态类字段前先查是否已有字典类型（按模块约定 code）；有则复用，没有则新建字典项再落库。

#### 用字典（内部字典）

- 存放：系统管理 → 字典类型 / 字典数据（内置种子 `IsBuiltin = true` 的不要给业务乱删）。
- **业务字典 Value**：优先有语义的英文字符串编码（`Pending` / `InProcess`），前端按字典翻译文案与 `TagStyle`。
- **与枚举双轨对齐时**（如 `common_status`、`gender`）：Value 使用枚举整数值的十进制字符串（`"0"` / `"1"`），保证代码分支与展示一致。
- 前端：下拉、筛选、表格展示按字典 `code` 拉取，不要在页面写死选项。
- 后端业务判断：集中为常量或字典编码常量，禁止散落魔法字符串；前端集中到 `shared` 常量 + 字典翻译。
- 新增业务字典：先加类型/数据，再在实体上存 Value；模块内注明字典编码（如 `dict:order_status`）。

**适合字典的例子：** 行业、证件类型、订单/工单业务状态、不良原因、自定义标签。

#### 用 int 枚举

- 定义位置：`src/Axis.Domain/Enums/XxxEnum.cs`，**一枚举一文件**；细则见 **§11**。
- 实体 / DTO 字段使用枚举类型；**禁止**无注释的裸 `int Status` 与魔法数字比较。

**必须用枚举的例子：** `MenuTypeEnum`、`DataScopeEnum`、`TenantTypeEnum`、`ConfigTypeEnum`。

#### 既要分支又要前端展示时（双轨对齐）

1. **权威在枚举**：业务分支只认枚举。  
2. **展示走字典**：字典 Value **必须与枚举整数值一致**。  
3. 禁止只改一侧；前端用字典标签，后端鉴权/过滤仍用枚举。

#### 禁止

- ❌ 无意义数字作为业务字典 Value（应 `InProcess` 而非 `"3"`，除非与枚举双轨）  
- ❌ `if (status == 1)` / `if (status == "doing")` 魔法判断  
- ❌ 把菜单类型、数据范围做成可后台乱改的字典  
- ❌ 把纯运营可配业务状态做成枚举，导致每次加选项都要发版  

### 2.5 字典与系统配置缓存（推荐并列为规范）

字典（`SysDict*`）与系统参数（`SysConfig`）读多写少、体量小、会被业务各处频繁引用，**适合缓存**。管理端分页/编辑仍查库；业务侧按 `code` 取值必须走缓存门面，禁止每次直查库。

#### 结论

| 项 | 结论 |
|---|---|
| 要不要缓存 | ✅ 要 |
| 何时加载 | 应用启动完成后预热（Warm-up）；未命中时懒加载回源并回填 |
| 何时更新 | 管理端 Create / Update / Delete / 启停 **写库成功后同步刷新或失效缓存** |
| 用什么 | 现有 `ICacheService`（EasyCaching）；多实例生产建议 `hybrid`/`redis`，开发可用 `memory` |
| 过期策略 | 字典/配置属「近永久」：设置较长 TTL（如 24h）作兜底，**以主动刷新为主**，不靠短 TTL 过期 |

#### 缓存键约定（写入 `CacheCatalog`）

```text
Axis:sys:dict:type:{tenantOrGlobal}:{dictTypeCode}     → 该类型下启用中的 DictData 列表
Axis:sys:dict:map:{tenantOrGlobal}:{dictTypeCode}      → Value→Label（及 Tag）字典，便于翻译
Axis:sys:config:item:{tenantOrGlobal}:{configCode}     → 单条配置值
Axis:sys:config:group:{tenantOrGlobal}:{groupCode}     → 分组下配置字典（可选）
```

- `tenantOrGlobal`：有租户用租户 Id，全局用 `g`。
- Key 生成统一走 `ICacheService.GenerateKey` + `CacheCatalog` 分组上的 `KeyPrefix`，禁止魔法字符串散落。
- **缓存管理台分组与前缀已合并**：在 `CacheCatalog` 追加一个 `CacheGroup` 静态字段并加入 `Groups` 即可；`CacheAdminAppService` 只消费目录。`GlobalRooted` = `{GlobalPrefix}{Separator}{KeyPrefix}`；`Absolute` = 完整前缀（不拼全局前缀）。

#### 推荐组件拆分

| 组件 | 职责 |
|---|---|
| `ISysDictCache` / `SysDictCache` | `GetItemsAsync(code)`、`GetLabelAsync(code, value)`；内部读缓存，miss 则查库回填 |
| `ISysConfigCache` / `SysConfigCache` | `GetValueAsync(code)`、`GetInt/Bool/...` 强类型扩展；同上 |
| `SysDictCacheWarmupHostedService`（或合并一个 `SysMetaCacheWarmupHostedService`） | 启动后加载全部启用字典类型与配置写入缓存 |
| `DictAppService` / `ConfigAppService` | 写操作成功后调用 cache 的 `RefreshTypeAsync` / `RefreshConfigAsync` 或 `Invalidate*` |

业务模块 **只依赖** `ISysDictCache` / `ISysConfigCache`，不要直接注入 `IRepository<SysDictData>` 做选项翻译。

#### 写路径（必须）

```text
管理端更新字典数据
  → 校验 + 写库
  → Refresh/Invalidate：该 dictTypeCode（及 map）缓存
  → （可选）若改了类型 Code，同时失效旧 Code 键

管理端更新配置
  → 写库
  → Refresh 该 configCode；若带 GroupCode 则刷新分组键
```

- 优先 **写穿刷新**（写库后立刻用新数据 `SetAsync`），避免短暂读到旧值。
- 多节点：使用 Redis/Hybrid 时，依赖 EasyCaching 总线使本地内存失效；仅 Memory 模式多实例会不一致，部署文档需标明。

#### 读路径（必须）

```text
业务需要性别下拉 / 翻译
  → await dictCache.GetItemsAsync("gender")
  → 禁止 Db.Queryable<SysDictData>()...

业务需要某开关配置
  → await configCache.GetValueAsync("sys.login.captchaEnabled")
```

管理端的 `PageAsync` / 详情编辑 **可以继续查库**（要最新编辑态与分页），不强制走缓存。

#### 租户与启用状态

- 只缓存 `Status == Enable` 的数据；禁用项从缓存移除。
- 租户级字典/配置：键中带 `TenantId`；读取时先租户键，未命中再回退全局 `g`（若产品需要覆盖语义，在 Cache 实现里写清并注释）。

#### 禁止

- ❌ 在各业务 Service 里自行 `ICacheService.Set` 字典片段，键名不统一  
- ❌ 更新库成功但不刷新缓存  
- ❌ 把管理端分页结果整页缓存当业务字典用  
- ❌ 缓存未启用的、软删的数据  

#### 落地顺序（实现时）

1. 增加 `CacheCatalog` 键前缀与 `ISysDictCache` / `ISysConfigCache`。  
2. 写路径挂上 Refresh。  
3. 启动 Warm-up HostedService。  
4. 规范 §2.4：业务取字典/配置改走 Cache 门面。  
5. 前端高频接口可增加「按 code 取字典项」只读 API（读缓存）。

## 3. 代码注释与文档规范

代码注释的目标是解释「**为什么这样做、有什么约束、违反后会发生什么**」，而不是把代码再翻译一遍。  
语言：简体中文。XML 中引用类型使用 `<see cref="..."/>`。

### 3.1.0 XML 注释格式强制要求

所有 XML 注释必须使用**完整多行形式**，禁止为减少行数而压缩注释。

**禁止：**

```csharp
/// <summary>是否逻辑删除。</summary>
public bool Deleted { get; set; }
```

**必须：**

```csharp
/// <summary>
/// 指示当前记录是否已经被逻辑删除；常规业务查询必须排除已删除记录。
/// </summary>
/// <remarks>
/// 该字段由平台删除流程维护，不允许客户端直接传入或覆盖。
/// </remarks>
public bool Deleted { get; set; }
```

**禁止**使用 `inheritdoc` 代替明确注释：

```csharp
/// <inheritdoc />
public Task CreateAsync(SaveRoleInput input, CancellationToken cancellationToken)
```

接口实现、抽象类实现和重写方法必须**重新说明当前实现的真实行为**：

```csharp
/// <summary>
/// 校验角色编码唯一后，将输入映射为角色实体并写入角色主表。
/// </summary>
/// <param name="input">新增角色所需字段；编码须全局（或租户内）唯一。</param>
/// <param name="cancellationToken">用于取消数据库写入操作的取消令牌。</param>
/// <returns>表示角色持久化操作的异步任务。</returns>
/// <remarks>
/// 此实现只负责角色主表写入，不处理菜单授权；授权见 <see cref="GrantMenusAsync"/>。
/// 编码冲突时抛出 <see cref="BusinessException"/>。
/// </remarks>
public Task CreateAsync(SaveRoleInput input, CancellationToken cancellationToken)
```

**公共方法**注释必须根据实际情况包含：

- 方法完成的业务职责。
- 每个参数的来源、用途和限制（`<param>`）。
- 返回值代表的具体结果（`<returns>`，非 void）。
- 可能抛出的主要异常（`<exception>` 或写在 `<remarks>`）。
- 当前实现**不负责**的行为边界。
- 幂等、事务、线程安全或性能方面的重要限制。

**公共属性**注释必须根据实际情况包含：

- 业务含义。
- 数据来源。
- 单位和精度（若适用）。
- 是否可空。
- 默认值或特殊取值。
- 是否允许客户端赋值。
- 是否属于敏感信息。
- 容易误用的限制。

**禁止**模糊注释，例如：「设备标识」「是否成功」「处理数据」「执行操作」「获取列表」「保存信息」。  
应说明：标识什么、成功代表什么、处理什么数据、执行到哪一步、返回什么范围、保存到哪里。

**CI / 架构检查建议拦截的正则：**

```regex
///\s*<summary>.*</summary>
///\s*<inheritdoc\s*/>
```

（单行 summary、以及单独的 inheritdoc。）

### 3.1.1 必须添加注释的对象

以下对象必须添加 XML 文档注释：

- `public` 类型（类、接口、record、结构体）。
- `public` 和 `protected` 方法。
- 对外公开的接口及其成员。
- DTO、Input、Output、Command、Query、PageQuery。
- 领域实体与关联实体。
- 枚举及**每一个**枚举成员。
- 配置 Options（如 `AxisAuthOptions`、`AxisCachingOptions`）。
- 事件 / 消息契约（如 `UserLoginEvent`、`AuditLogEvent`）。
- Endpoint 类（说明路由语义与权限边界）。
- Validator、Mapster `IRegister`。
- 仓储接口及对外公共方法。
- 关键常量（如 `CacheCatalog`、`SystemPermissionCodes`、`ClaimConst`）。
- 对外扩展方法。
- 会被其他模块调用的公共方法。

示例：

```csharp
/// <summary>
/// 使用刷新令牌哈希查找未吊销会话，在条件消费成功后签发新的令牌对。
/// </summary>
/// <param name="refreshToken">客户端持有的明文刷新令牌；服务端仅存储其哈希。</param>
/// <param name="cancellationToken">取消令牌。</param>
/// <returns>新的 AccessToken 与 RefreshToken 配对；失败时不返回部分成功状态。</returns>
/// <remarks>
/// 此方法在工作单元内执行；并发下同一刷新令牌仅允许一个请求消费成功。
/// 不负责读写 Cookie，Cookie 由 Endpoint / <see cref="IRefreshTokenCookieService"/> 处理。
/// </remarks>
/// <exception cref="BusinessException">令牌无效、已使用、已过期或账号冻结时抛出。</exception>
Task<IssuedTokenPair> RefreshTokenAsync(string refreshToken, CancellationToken cancellationToken = default);
```

### 3.1.3 业务逻辑注释

以下复杂逻辑必须在代码**附近**用 `//` 说明原因（解释为什么，不是复述语句）：

- Refresh Token 一次性轮换与条件更新并发闸门。
- Refresh Token 族复用检测（已消费令牌再次出现 → 整族吊销）。
- 写请求时间戳 + Nonce 防重放（已登录 POST/PUT/PATCH/DELETE；匿名与 GET 跳过）。
- 管理端防重放附加 HMAC-SHA256（密钥为 AccessToken；串 `METHOD&path&timestamp&nonce`）；OpenAPI AccessKey 签名另案。
- OpenAPI Signature 认证：`AuthSchemes(SignatureAuthenticationDefaults.AuthenticationScheme)` + `.SkipAntiReplay()`；签名串 `METHOD&path&accessKey&timestamp&nonce`。
- 对外接口可用 `[SkipAntiReplay]` / `.SkipAntiReplay()` 跳过防重放头校验。
- 密码错误次数锁定与解锁。
- SM2 解密失败与「账号或密码错误」统一文案（防枚举）。
- 超级管理员权限绕过。
- 多表写入顺序、先删后插授权、软删与关联清理。
- 租户过滤 / 数据范围过滤条件的业务含义。
- 忽略全局过滤器（`IgnoreFilter`）的原因与风险。
- 指令/请求幂等键处理。
- 缓存预热、写穿刷新与多节点失效。
- 为兼容旧数据或迁移而保留的特殊逻辑。
- 为性能而采用的非直观实现（如手写投影代替 Mapster）。
- 字典 Value 与枚举数值双轨对齐处。

**合格：**

```csharp
// 条件更新是轮换的并发闸门：同一 Refresh Token 只能有一个请求成功，
// 其余并发请求必须视为会话失效，防止令牌重放。
var affected = await refreshTokenRepo.TryConsumeAsync(model.Id, now, ct);
if (affected != 1)
    throw SessionExpired();
```

**不合格：**

```csharp
// 更新 IsUsed
await refreshTokenRepo.TryConsumeAsync(model.Id, now, ct);
```

### 3.1.4 禁止的注释方式

禁止：

- 使用单行 `/// <summary>...</summary>`。
- 使用 `/// <inheritdoc />`（或带 cref的 inheritdoc）代替当前实现的明确说明。
- 只写「标识」「状态」「是否成功」「处理数据」「获取列表」「保存信息」等无法说明真实业务含义的注释。
- 公共方法缺少参数、返回值或关键边界说明。
- 注释与实际代码不一致。
- 大段保留已废弃代码；用注释代替版本管理。
- 使用「临时处理」「后面再改」但没有任务编号和期限。
- 注释中写个人情绪或无意义描述。
- 每一行代码都增加重复注释。
- 只写「新增」「修改」「删除」等无业务含义注释。
- 在注释中记录密码、Token、私钥、生产连接串或真实地址。

## 4. 入参检测（单独划分）

### 4.1 分层原则

| 校验类型 | 放哪里 | 示例 |
|---|---|---|
| 格式 / 必填 / 长度 / 范围 | `Validators/*Validator.cs`（FastEndpoints Validator） | 账号非空、密码长度 |
| 业务唯一性 / 存在性 / 状态机 | `AppService` | 账号已存在、内置字典不可删 |
| 权限 | Endpoint `RequirePermission` | `sys:role:create` |

**禁止：**

- 在 Endpoint `HandleAsync` 里手写一长串 `if (string.IsNullOrEmpty)`。
- 只在 DTO 上堆 DataAnnotations、又在 Service 重复同一套格式校验（DataAnnotations 可保留作文档/Swagger 提示，**权威校验以 Validator 为准**）。
- 把「账号是否存在」放进 Validator 并注入仓储（避免校验层变胖）；唯一性放 AppService。

### 4.2 Validator 文件规范

路径：`src/Axis.Application/{模块}/Validators/SaveRoleInputValidator.cs`

```csharp
using FastEndpoints;
using FluentValidation;

namespace Axis.Application.System.Role.Validators;

/// <summary>
/// <see cref="SaveRoleInput"/> 的入参格式校验。
/// <para>仅做格式与必填；业务唯一性由 <see cref="IRoleAppService"/> 负责。</para>
/// </summary>
public sealed class SaveRoleInputValidator : Validator<SaveRoleInput>
{
    /// <summary>
    /// 注册字段规则。
    /// </summary>
    public SaveRoleInputValidator()
    {
        RuleFor(x => x.Name)
            .NotEmpty().WithMessage("角色名称不能为空")
            .MaximumLength(64).WithMessage("角色名称不能超过 64 个字符");

        RuleFor(x => x.Code)
            .NotEmpty().WithMessage("角色编码不能为空")
            .MaximumLength(64).WithMessage("角色编码不能超过 64 个字符")
            .Matches(@"^[a-zA-Z][a-zA-Z0-9_]*$").WithMessage("角色编码须以字母开头，仅含字母数字下划线");
    }
}
```

对应 Endpoint **不要**再抄一遍校验；保证 Request 类型与 Validator 的泛型一致，FastEndpoints 会自动发现（`07-Assembly.json` 已扫描 `Axis.Application`）。

> **工程依赖：** `Validator<T>` 来自 FastEndpoints。若 `Axis.Application` 编译找不到该基类，请为 Application 增加对 `FastEndpoints` 的包引用，或增加对 `Axis.Infrastructure` 的项目引用（二选一，推荐直接包引用以免加深分层耦合）。DataAnnotations 可继续留在 DTO 上作 Swagger 提示，但**不以它为权威校验**。

### 4.3 DTO 上的注解

- 可保留 `[Required]` / `[MaxLength]` 作为 Swagger 提示与双重保险。
- 每个公开属性仍需 XML 注释（见 §3）。
- 错误消息面向用户，中文、可执行（「不能为空」而不是「Invalid」）。

### 4.4 校验失败响应

框架已将 `ValidationFailureException` 映射为统一信封（`ResultCodes.ValidationFailed`）。  
业务代码 **不要** catch 后改写成 `BusinessException`，除非要合并为领域语义错误。

## 5. AppService 与仓储如何拆

### 5.1 决策表

| 场景 | 放 AppService | 放 Repository |
|---|---|---|
| 用例步骤编排（先校验再写再发事件） | ✅ | ❌ |
| 抛业务异常、拼装返回 DTO | ✅ | ❌ |
| 单表按 Id 查 / 简单增删改 | ✅ 可走 `IRepository<T>` 或 `BaseAppService` | 可选 |
| 多表 Join、专用投影、条件更新、忽略过滤器 | ❌（可调用） | ✅ 专用方法 |
| 登录找用户带 Org、Token 条件消费 | ❌ | ✅ |
| 「是否存在未完成关联」等可复用查询 | 调用仓储 | ✅ 语义化方法名 |

### 5.2 专用仓储何时新建

满足任一条件即应新建 `ISysXxxRepository`：

1. 同一查询在 ≥2 个用例出现；
2. 需要 Join / 子查询 / 条件更新 / `IgnoreFilter`；
3. 方法名能表达领域语义（如 `TryConsumeAsync`、`FindByAccountWithOrgAsync`）；
4. 为未来数据权限预留统一过滤入口。

**反例：** 只有 `GetById` + `Insert` 的模块，使用 `IRepository<SysXxx>` 即可，不必空仓储。

### 5.3 AppService 禁止事项

```csharp
// ❌ 禁止：在 AppService 里堆大段 SqlSugar 投影（应下沉仓储或用 Mapster + 仓储返回实体后再映射）
return await Repo.AsQueryable()
    .LeftJoin<SysOrg>(...)
    .Select((u, o) => new UserDto { ... 40 个字段 ... })
    .ToPagedListAsync(...);

// ✅ 推荐：
// var page = await userRepo.PageAsync(query, ct);
// return page.Adapt<SqlSugarPagedList<UserDto>>(); // 或仓储直接返回 DTO（只读查询允许）
```

只读复杂查询允许仓储 **直接返回 DTO**（避免无意义的实体往返），但 DTO 类型仍定义在 Application 层时，注意项目引用方向：  
更干净的做法是仓储返回「查询模型」或由 Application 用 `IMapper` 映射；过渡期可在仓储方法返回 Application DTO，但 **不要**让 Domain 项目引用 Application。

### 5.4 当前账户与租户

- 写操作：`TenantId = CurrentAccount.TenantId` 在 AppService 赋值，并注释说明。
- 读过滤：优先未来全局过滤器；过渡期 `WhereIF(CurrentAccount.TenantId.HasValue, ...)` 必须注释。
- **禁止**在仓储硬编码「当前用户」（仓储可接收 `tenantId` 参数）。

## 6. BaseAppService 使用规范

### 6.1 定位

`BaseAppService<TEntity>` 提供**单实体**常见骨架：按 Id 查、创建、更新、删除、批量删、简单分页辅助。  
它是便利基类，**不是**业务模型本身。

### 6.2 何时继承

| 情况 | 建议 |
|---|---|
| 标准 CRUD 聚合（Role/Org/Pos/Config…） | ✅ 继承，复用审计字段填充前的通用删除/存在校验 |
| 跨聚合编排（Author、含大量领域规则的 User） | ⚠️ 可继承，但复杂方法不要强行复用基类签名（用 `new` 要谨慎） |
| 无实体根、纯领域服务 | ❌ 不继承 |

### 6.3 使用约束

1. **优先调用基类语义清晰的方法**；覆盖时保持异常消息风格一致（`BusinessException`）。
2. **禁止**在派生类把 `Db`（`ISqlSugarClient`）当成「第二个仓储」随便写；新增复杂查询请加仓储方法。
3. 删除策略全仓统一为**软删除**（`Deleted = true`）时，应覆盖 `DeleteAsync` / `DeleteManyAsync`，**禁止**继续调用硬删 `Deleteable`（基类若仍是硬删，覆盖方法须带合规 TODO，见 §3.1.5）。
4. 基类 `GetAsync` 返回实体；对外 API 需要 DTO 时，派生类应提供 `GetDtoAsync` 或映射后返回，**不要**把实体直接塞给 Endpoint。
5. 不要为了用基类而把不相关实体塞进同一个 `BaseAppService<T>`。

### 6.4 推荐继承写法

```csharp
/// <summary>
/// 岗位管理应用服务：负责岗位编码唯一校验、持久化与租户字段补全。
/// </summary>
public sealed class PositionAppService(
    IRepository<SysPos> repository,
    ISqlSugarClient db,
    ICurrentAccount currentAccount,
    IMapper mapper)
    : BaseAppService<SysPos>(repository, db, currentAccount), IPositionAppService, IAutoInject
{
    /// <summary>
    /// 在编码唯一的前提下创建岗位，并写入当前登录租户标识。
    /// </summary>
    /// <param name="input">岗位名称、编码及排序等字段；编码租户内唯一。</param>
    /// <param name="ct">取消令牌。</param>
    /// <remarks>
    /// 不处理岗位与用户的关联变更。编码冲突时抛出 <see cref="BusinessException"/>。
    /// </remarks>
    public async Task CreateAsync(SavePositionInput input, CancellationToken ct = default)
    {
        await EnsureCodeUniqueAsync(input.Code, excludeId: null, ct);

        var entity = mapper.Map<SysPos>(input);
        entity.Id = 0; // Input 若带 Id，置 0 交给 AOP 生成雪花
        entity.TenantId = CurrentAccount.TenantId;

        await CreateAsync(entity, ct);
    }
}
```

## 7. Mapster 映射规范

### 7.1 注册与发现

- 配置见 `Config/07-Assembly.json` → `Assembly.Mapster`（当前扫描 `Axis.Application|Axis.Domain`）。
- 映射配置实现 `IRegister`，放在模块 `Mappings/` 下，启动时由 `AddObjectMapper()` 扫描。
- 全局策略：`NameMatchingStrategy.Flexible` + `PreserveReference(true)`，**不要**在业务代码再次改全局默认。

### 7.2 何时用 Mapster

| 场景 | 建议 |
|---|---|
| Input → 实体（字段同名为主） | ✅ `mapper.Map<TEntity>(input)` 或 `input.Adapt<TEntity>()` |
| 实体 → Dto（同名为主） | ✅ Mapster |
| 需忽略密码、重算字段、自定义转换 | ✅ `IRegister` 显式配置 |
| 分页 Join 多表投影（字段来自多实体） | ⚠️ 仓储 `Select` 投影或自定义 Register；避免先查实体再硬凑 |
| 热路径大规模循环 | ⚠️ 预编译配置已启用；避免每次 `new TypeAdapterConfig` |

### 7.3 Register 示例

```csharp
using Mapster;

namespace Axis.Application.System.User.Mappings;

/// <summary>
/// 用户模块对象映射注册：定义创建入参到实体、实体到列表 DTO 的字段规则。
/// </summary>
public sealed class UserMappingRegister : IRegister
{
    /// <summary>
    /// 向全局 <see cref="TypeAdapterConfig"/> 注册用户相关映射，并忽略密码等敏感/服务端字段。
    /// </summary>
    /// <param name="config">Mapster 全局配置实例，由启动扫描传入。</param>
    /// <remarks>
    /// 密码必须在用例内单独 Hash，禁止从 Input 映射明文到实体。
    /// </remarks>
    public void Register(TypeAdapterConfig config)
    {
        config.NewConfig<CreateUserInput, SysUser>()
            .Ignore(dest => dest.Id)
            .Ignore(dest => dest.Password)
            .Ignore(dest => dest.TenantId);

        config.NewConfig<SysUser, UserDto>()
            .Map(dest => dest.OrgName, src => src.SysOrg != null ? src.SysOrg.Name : null);
    }
}
```

### 7.4 使用方式

- 应用服务构造注入 `IMapper`（推荐，便于测试），或在简单场景使用 `Adapt<T>()` 扩展方法。
- **禁止**在 Endpoint 做映射；Endpoint 只转交 Input/Output。
- **禁止**映射敏感字段（密码 Hash、RefreshToken 明文等）到出参 DTO。
- 映射失败应在开发期暴露；不要空 `catch` 吞掉。

### 7.5 Insert / Update 字段赋值规则（强制）

业务字段用 **Mapster** 从 Input 映射到实体；主键与审计字段交给 SqlSugar **`DataExecuting` AOP**，**禁止**在用例里再手写一长串同名赋值。

实现位置：`src/Axis.Infrastructure/Components/Database/ServiceCollectionExtensions.cs` → `SetDbAop` → `db.Aop.DataExecuting`。  
仅对 **对象写** 生效：`InsertByObject` / `UpdateByObject`（即 `Insertable(entity)` / `Updateable(entity)`）；`SetColumns` 表达式更新不走完整对象列回调时，勿依赖本 AOP。

#### AOP 自动赋值一览（与代码一致）

| 时机 | 字段 | 条件 | 写入值 |
|---|---|---|---|
| Insert | `long` 主键 `Id` | 当前值为 `null` 或 `0` | `YitIdHelper.NextId()` |
| Insert | `CreatedTime` | 已登录，且值为 `null` / `DateTime.MinValue` | `DateTime.Now` |
| Insert | `CreatedBy` | 已登录，且值为 `null` / `0` | `ICurrentAccount.Id` |
| Insert | `Creator` | 已登录，且为空字符串 | `ICurrentAccount.RealName` |
| Update | `ModifiedTime` | 始终 | `DateTime.Now` |
| Update | `ModifiedBy` | 已登录 | `ICurrentAccount.Id` |
| Update | `Modifier` | 已登录 | `ICurrentAccount.RealName` |

「已登录」判定：`ICurrentAccount` 可解析且 `Id != 0`（来自当前 `HttpContext`）。无用户上下文时 **仍可能生成雪花 Id**，但操作人字段不会填。

#### 用例内仍须手写

| 字段 | Insert | Update | 由谁赋值 |
|---|---|---|---|
| 业务同名字段（Name、Code、Status…） | ✅ | ✅ | `mapper.Map` / `mapper.Map(input, entity)` |
| `TenantId` | ✅ 必写 | 一般不改 | AppService：`CurrentAccount.TenantId`（**AOP 不处理**） |
| 密码等敏感 / 重算字段 | 映射后单独赋 | 独立接口 | AppService（如 BCrypt）；`IRegister` 须 Ignore |

用例侧约定：`Id` 保持 `0`（或 Register Ignore）；Created* / Modified* **不要**再赋。

```csharp
// ✅ 创建：Mapster + TenantId；Id / 审计交给 AOP
public async Task CreateAsync(SaveRoleInput input, CancellationToken ct = default)
{
    await EnsureCodeUniqueAsync(input.Code, null, ct);

    var entity = mapper.Map<SysRole>(input);
    entity.Id = 0;
    entity.TenantId = CurrentAccount.TenantId;

    await Db.Insertable(entity).ExecuteCommandAsync(ct);
}

// ✅ 更新：先查实体再 Map 覆盖；修改审计交给 AOP
public async Task UpdateAsync(long id, SaveRoleInput input, CancellationToken ct = default)
{
    var entity = await Repo.AsQueryable().Where(item => item.Id == id).FirstAsync(ct)
                 ?? throw new BusinessException("角色不存在");
    await EnsureCodeUniqueAsync(input.Code, id, ct);

    mapper.Map(input, entity);
    await Repo.AsUpdateable(entity).ExecuteCommandAsync(ct);
}

// ❌ 禁止：逐字段 new 实体 + 手写 Id / Created* / Modified*
await Db.Insertable(new SysRole
{
    Id = YitIdHelper.NextId(),
    Name = input.Name,
    // ...
    CreatedBy = CurrentAccount.Id,
    Creator = CurrentAccount.RealName,
    CreatedTime = DateTime.Now
}).ExecuteCommandAsync(ct);
```

注意：

- AOP 仅在 **HTTP 请求内能解析到 `ICurrentAccount`** 时填充操作人；后台 Job / 无用户上下文时须自行赋值或注入系统账户，并注释说明。
- Input 含 `Id` 时，创建路径必须 `entity.Id = 0` 或 Register `Ignore(dest => dest.Id)`，**禁止**信任前端传入的主键。
- 查询出参投影用 `Select(..., true)`（§13.3），与此处 Input→实体的 Mapster **不要混用概念**。

## 8. FastEndpoints 使用规范

### 8.1 基类选择

| 基类 | 场景 |
|---|---|
| `AxisEndpoint<TReq, TRes>` | 有入参有出参（分页、详情） |
| `AxisEndpoint<TReq>` | 有入参无出参（创建/更新/删除，统一空 data） |
| `AxisEndpointWithoutRequest<TRes>` | 无入参有出参（验证码、当前用户） |
| `AxisEndpointWithoutRequest` / Blank | 无入参无出参（极少） |

### 8.2 `Configure()` 标准写法

```csharp
public override void Configure()
{
    // 1. 匿名 / 路由
    // AllowAnonymous();                 // 仅登录、刷新、验证码等
    Post("/sys/role");

    // 2. 文档
    Summary(s =>
    {
        s.Summary = "新增角色";
        s.Description = "创建角色基础信息，不含菜单授权";
    });

    // 3. 分组、权限、事务、幂等（按需链式）
    Options(x => x.WithTags("角色管理")
        .WithGroupName(nameof(ApiGroupEnum.AdminSystemModule))
        .RequirePermission(SystemPermissionCodes.Role.Create)
        // 多表写或「删主表 + 清关联」时必须加：
        // .Transactional()
        // 支付/提交类可加：
        // .Idempotent()
    );
}
```

### 8.3 必须使用的框架能力

| API | 用途 |
|---|---|
| `RequirePermission(...)` | 权限码，来自 `SystemPermissionCodes`，禁止魔法字符串 |
| `Transactional()` | 多表写入、删主清从、授权「先删后插」 |
| `Idempotent()` | 重复提交敏感操作 |
| `AllowAnonymous()` | 仅公开接口；默认需登录 |
| `ThrowBusiness` / `EnsureFound` / `EnsureTrue` | 端点内短断言（优先仍把规则放 AppService） |
| `Disable.xxx` / 响应头 `Cache-Control` | 登录刷新等禁止缓存 |

### 8.4 `HandleAsync` 瘦身规则

```csharp
public override async Task HandleAsync(SaveRoleInput req, CancellationToken ct)
{
    // ✅ 只编排
    await service.CreateAsync(req, ct);
}

// ❌ 禁止在 HandleAsync 写业务、SQL、复杂分支
```

HTTP 特有逻辑（Cookie、响应头）可以留在 Endpoint，但要注释清楚，且 **不要**渗入 AppService（Author 刷新 Cookie 是例外中的边界：Cookie 读写在 Endpoint / `IRefreshTokenCookieService`，轮换算法在 AppService）。

### 8.5 路由与动词

| 操作 | HTTP | 路径示例 |
|---|---|---|
| 分页 | GET | `/sys/role/page` |
| 详情 | GET | `/sys/role/{Id}` |
| 新增 | POST | `/sys/role` |
| 更新 | PUT | `/sys/role/{Id}` |
| 删除 | DELETE | `/sys/role/{Id}` |
| 命令 | POST | `/sys/role/{Id}/menus`、`/sys/user/{Id}/reset-password` |

- 前缀：`/sys/{module}`；系统管理模块用 `sys`。
- 路径参数与 Request 属性名一致（如 `Id`），便于模型绑定。

### 8.6 事务标注规则

| 操作 | 是否 `Transactional` |
|---|---|
| 单表 Insert/Update | 通常否 |
| 删除主数据并清理关联 | **是** |
| 授权（先删后插关系表） | **是** |
| 字典类型 + 级联数据 | **是** |
| Token 轮换（条件更新 + 插入） | 在 AppService 内显式 UoW亦可，须注释 |

## 9. 应用服务编写规范（补充）

### 9.1 方法结构建议

```csharp
public async Task CreateAsync(SaveRoleInput input, CancellationToken ct = default)
{
    // 1. 业务前置校验（唯一性、引用存在）
    await EnsureCodeUniqueAsync(input.Code, null, ct);

    // 2. Mapster 映射 + 仅补 TenantId（Id / 审计见 §7.5，由 AOP 填充）
    var entity = mapper.Map<SysRole>(input);
    entity.Id = 0;
    entity.TenantId = CurrentAccount.TenantId;

    // 3. 持久化
    await Repo.InsertAsync(entity); // 或基类 CreateAsync

    // 4. 领域事件（如有）
    // await eventPublisher.PublishAsync(...);
}
```

### 9.2 异常

- 可预期业务失败：`BusinessException` / `BusinessException(ResultCodes.Xxx, message)`。
- 未登录 / 无权限：优先让权限管道处理；服务内发现则用 `Unauthorized` / `Forbidden`。
- 禁止抛裸 `Exception`、禁止返回 `null` 表示「未登录」。

### 9.3 接口与实现（强制分文件）

- 每个 AppService **必须**有接口：`IXxxAppService.cs` 与 `XxxAppService.cs` **禁止同文件**。
- 实现类注册 `IAutoInject`（或等价约定）。
- 接口与实现均须按 §3 写明真实行为；**禁止**用 `inheritdoc` 敷衍。
- 禁止在实现文件中再定义 `PageQuery` / `Dto` / `Input`（一律进 `Dto/`）。

### 9.4 业务编码必须走统一编码规则

工单号、物料号、报工号、检验单号等业务编码 **必须** 注入 `ICodeGenerator`，按域内常量取号：

```csharp
var code = await codeGenerator.NextAsync(CodeRuleCodes.WorkOrder, context, ct);
entity.Code = code.Value;
```

- 规则在「系统管理 → 编码规则」维护；调用键收成 `CodeRuleCodes` 或各域 `*CodeRuleCodes`，禁止魔法字符串。
- 禁止模块内拼接日期流水、禁止无锁 `max+1`。
- 本厂生成走 `NextAsync`（占流水）；外来码走 `ValidateAsync`，不占用流水。
- 模板含 `{Material}` / `{Line}` 等上下文占位符时，调用方必须传入对应 `Variables`，禁止静默空串。
- 取号与业务写同事务；回滚可空号，已提交号不回收。

### 9.5 事件、Outbox 与租户 Scope

进程内总线仍是 FastEndpoints Event（<c>IEventPublisher</c> / <c>AxisEventHandler</c>），**禁止**再引入 MediatR。

| 场景 | 用法 |
|---|---|
| 同模块、必须立刻写完（公告→收件箱） | <c>IEventPublisher.PublishAsync</c> |
| 审计 / 登录日志 | <c>PublishFireAndForgetAsync</c> |
| 跨模块副作用、出站集成、MES 工单完工 | 继承 <c>IntegrationEvent</c>，<c>IOutbox.EnqueueAsync</c> |

约定：

- 新 MES 事件必须带 <c>EventId</c> + <c>TenantId</c>；缺省由发布门面 / Outbox 入队时补齐。
- 集成事件 Handler 必须幂等；失败靠 Outbox 重试，默认 <c>ShouldRethrow = false</c>。
- 禁止 Handler 内对 ERP 发 HTTP 并包进业务事务。
- 事件放 <c>Application/{Area}/{Module}/Events/</c>，Handler 放 <c>EventHandlers/</c>；禁止塞进 <c>Infrastructure/Components/EventBus/Events/</c>（那里只放登录、审计、文件）。
- Outbox 表 <c>axis_outbox</c> 由 Dispatcher 投递。默认传输 <c>InProcess</c>；多实例或需 Broker 时：实现 <c>IOutboxTransport</c>（Name = <c>RabbitMq</c>）、把 <c>Outbox:Transport</c> 改为 <c>RabbitMq</c>、从 <c>Outbox:RabbitMq</c> 读连接参数；消费端调 <c>IIntegrationEventIngress.HandleAsync</c>。禁止改 <c>IOutbox.EnqueueAsync</c> 与表结构。
- Job / 后台：<c>await tenantScope.RunAsync(tenantId, ct => ..., ct)</c>。

## 10. 类、方法与文件规模限制

### 10.1 方法规模

建议：

- 单个方法不超过 **50 行**有效代码（不含空行与纯注释行）。
- 单个方法参数不超过 **5 个**；超过时使用参数对象（Input / Query / Context）。
- 嵌套层级不超过 **3 层**（`if` / `for` / `using` 等合计）。
- 一个方法只完成一个明确职责。

超过限制时应优先：

- 提取领域方法 / 私有方法。
- 使用策略模式、责任链、状态机。
- 使用专用参数对象。

**禁止**出现超长「万能方法」同时完成：验证、查询、映射、写库、发事件、记日志、拼装返回结果等全部步骤硬堆在一个方法里。编排可以在 AppService，但各步骤应下沉为可命名的私有方法或协作服务。

### 10.2 类规模

- 建议单个业务类不超过 **500 行**有效代码。
- 以下名称通常意味着职责过多，评审重点检查：`*Service`（无前缀语义）、`CommonService`、`DataService`、`Manager`、`Helper`、`Processor`、`Handler`、`Utils`。
- 若确实使用，类名必须补充具体业务语义，例如：`UserPasswordResetService`、`RoleMenuGrantService`、`RefreshTokenRotationService`、`LoginLockoutService`。
- Author / 系统管理中的「上帝服务」超过 500 行必须拆分（见 §12 收敛顺序）。

### 10.3 文件规范

- 一个文件原则上只定义 **一个公共类型**。
- 文件名必须与公共类型名一致。
- 嵌套类型仅用于强关联且不会复用的场景。
- 禁止在一个文件中堆放多个无关 DTO（与 §2.1 一致）。
- 禁止使用 `#region` 隐藏过长类；应拆分类/文件。

## 11. 常量、枚举与业务字典规范

与 §2.4 互补：§2.4 负责「字典还是枚举」选型；本节约束魔法值、枚举形态与集中定义。

### 11.1 禁止魔法值

禁止：

```csharp
if (status == 3) { }
```

应使用：

```csharp
if (status == StatusEnum.Disable) { }
```

或业务字典 Value / 值对象。

以下内容必须集中定义（常量类、枚举或配置，禁止散落字面量）：

- 缓存 Key 模板（`CacheCatalog`）。
- HTTP Header 名称、Cookie 名称。
- 错误码 / 业务码（`ResultCodes`）。
- 权限码（`SystemPermissionCodes`）。
- Claim 名称（`ClaimConst`）。
- 固定协议/消息类型（若有）。
- 稳定状态机与账号类型等枚举。
- 默认超时、锁定阈值、分页上限等（常量或 Options）。

### 11.2 枚举规范

- **新建枚举**必须以 `Unknown = 0`（或业务上等价的「未知/未指定」）作为首成员；其后成员从 1 递增显式赋值。
- 持久化枚举值**发布后不得重排、不得改变已有成员含义**；只允许追加。
- 枚举成员必须有完整多行 XML 注释（§3）。
- 不允许使用中文枚举名；对外展示名称通过字典、描述或本地化处理。
- 第三方/厂家原始枚举不得直接作为平台公共枚举；需映射到平台枚举。
- 存量枚举（如 `StatusEnum` 以 `Disable = 0` 表示禁用）不强制立刻插入 `Unknown`，但**禁止为对齐本条而改已有数值**；新枚举一律遵守本条。

```csharp
/// <summary>
/// 账号类型（驱动超管判断与权限边界，不可用字典替代权威逻辑）。
/// </summary>
public enum AccountTypeEnum
{
    /// <summary>
    /// 未知或未指定。
    /// </summary>
    Unknown = 0,

    /// <summary>
    /// 普通用户。
    /// </summary>
    User = 777,

    /// <summary>
    /// 系统管理员。
    /// </summary>
    SysAdmin = 888,

    /// <summary>
    /// 超级管理员。
    /// </summary>
    SuperAdmin = 999
}
```

（上例数值若与种子字典已对齐则保持；新建业务枚举优先 `0,1,2,3…` 连续赋值。）

### 11.3 业务字典

需要运营配置、租户自定义或多语言展示的内容应使用业务字典，不应编译成枚举（细则同 §2.4）。

- 业务状态类字典 Value 使用**有语义的编码字符串**（如 `InProcess`），不要用无意义数字（除非与平台枚举双轨对齐）。
- 新增状态字段前先复用已有字典类型，避免同一业务多套 code。

| 适合枚举 | 适合业务字典 | 适合裸 int + 注释 |
|---|---|---|
| 稳定状态机、协议/动作类型 | 行业、业务状态、标签、原因码 | 仅 0/1/2 且永不扩展、无需可配文案 |
| 菜单类型、数据范围、租户隔离 | 运营可增删的下拉选项 | 须在属性注释逐值写清含义 |

### 12.1 Helper 限制

禁止创建无边界的：`CommonHelper`、`DataHelper`、`StringHelper`、`ObjectHelper`、`Utils`、`AxisUtils`。

Helper 只允许用于：

## 13. SqlSugar 开发规范

### 13.1 使用边界

SqlSugar 用于：控制面 CRUD、普通业务查询、事务、报表、批量业务操作。

高频或专用写入若使用 Npgsql COPY 等，必须通过抽象接口，不得绕过统一数据访问边界（Repository / UoW）。

### 13.2 Client 生命周期

- 使用框架推荐的线程安全 Scope / 客户端方式（当前为请求内 Scoped）。
- 禁止将非线程安全数据库上下文存入静态字段。
- Repository 不得缓存 `ISugarQueryable` 等查询对象跨请求使用。
- 不得在多线程中共享未确认线程安全的事务上下文。

### 13.3 查询要求（含联表与投影，必须）

#### 基础要求

必须：

- 只查询所需字段（避免无必要 `SELECT *`）。
- 大列表必须分页；明确排序。
- 对租户数据强制过滤（全局过滤器或统一仓储条件）。
- 使用参数化查询。
- 复杂 SQL 查看生成 SQL 与执行计划；高频查询建立合适索引。

禁止：

- `ToList()` 后再内存筛选大数据。
- N+1 查询；循环内逐条查询。
- 无条件全表查询。
- 将用户输入直接拼接到 SQL。
- 在列上随意使用导致索引失效的函数。
- 对超大集合未评估的 `Contains`（应用侧先限流/分批）。
- 不受控动态表名和字段名。

#### 关联与投影（强制，反 N+1）

- 关联数据优先用 **SQL 联表**一次取回：`LeftJoin` / `InnerJoin`，或 `Subqueryable` 子查询；**禁止**「先查主表再 `foreach` 逐条查子表」。
- 列表 / 详情所需的关联字段（名称、状态文案、数量、汇总等）在查询时用 **`Select` 投影**一次带回，不在内存里逐条补数据。
- 数量 / 进度 / 齐套等统计优先用 SQL 聚合（`GroupBy` / `Sum` / 子查询计数）算好返回，避免在 C# 里多次查库累加。
- 批量场景传 id 数组用 `Contains`（生成 `IN`）**一次查**；禁止在服务端循环里逐条 `FirstAsync` / `GetById`。

#### `Select(..., true)` 同名自动投影（推荐）

SqlSugar 的第二个参数 `true` 表示：**DTO 与实体（或主表）同名字段自动填充**，只手写差异 / 联表字段。只查 DTO 上存在的列，避免 `SELECT *`，也避免一长串同名赋值。

| 场景 | 写法 |
|---|---|
| 单表，DTO 字段与实体同名为主（如 `SysRole` → `RoleDto`） | `.Select(item => new RoleDto(), true)` |
| 联表，多数同名 + 少量来自他表 | `.Select((u, o) => new UserDto { OrgName = o.Name }, true)` |
| 字段几乎全不同、或需复杂表达式 | 显式写全 `Select`；或仓储返回实体后用 Mapster |

```csharp
// ✅ 单表同名：自动投影
var page = await Repo.AsQueryable()
    .WhereIF(...)
    .OrderBy(item => item.OrderNo)
    .Select(item => new RoleDto(), true)
    .ToPagedListAsync(query.Page, query.PageSize);

// ✅ 联表：同名自动填，只写差异字段
var page = await userRepo.AsQueryable()
    .LeftJoin<SysOrg>((u, o) => u.OrgId == o.Id)
    .Where((u, o) => ...)
    .OrderBy((u, o) => u.OrderNo)
    .Select((u, o) => new UserDto { OrgName = o.Name }, true)
    .ToPagedListAsync(page, pageSize);

// ❌ 同名字段逐条手写（冗余，易漏改）
.Select(item => new RoleDto
{
    Id = item.Id,
    Name = item.Name,
    Code = item.Code,
    // ...
})

// ❌ N+1
var users = await userRepo.GetListAsync();
foreach (var u in users)
{
    u.OrgName = (await orgRepo.GetByIdAsync(u.OrgId))?.Name;
}
```

注意：

- `true` **不能**替代 Mapster 的 Input→实体映射；它只用于 **查询投影**（SQL `Select`）。
- 复杂多表、大段投影仍应下沉到 Repository（见 §5.3）；单表同名投影可留在 AppService。
- 密码等敏感列不得出现在出参 DTO 上；DTO 无该属性则不会被投影出来。

```csharp
// ✅ 批量 IN
var ids = input.Ids.Distinct().ToArray();
var map = await repo.AsQueryable()
    .Where(x => ids.Contains(x.Id))
    .Select(x => new { x.Id, x.Name })
    .ToListAsync(ct);

// ❌ 循环单查
foreach (var id in ids)
    await repo.GetFirstAsync(x => x.Id == id);
```

#### 接口粒度（与查询一体设计）

- 主表 + 明细 + 汇总能一个接口返回的，就设计成**一个接口**（一次查询或一次仓储方法内完成），减少前后端往返。
- 确需拆接口时，提供**批量查询**接口（传 id/code 数组），禁止逼前端循环调详情。

完整前后端效率约定见 **§13.9**。

### 13.4 Repository 规范

Repository 应表达**领域查询语义**，不是 SqlSugar API 的简单搬运。

推荐：

```csharp
Task<SysUser?> FindByAccountWithOrgAsync(string account, CancellationToken ct = default);
```

不推荐：

```csharp
ISugarQueryable<SysUser> Query();
```

禁止将可变查询对象暴露到 Application 或 Endpoint。Application 可通过仓储方法拿结果；过渡期使用 `IRepository<T>.AsQueryable()` 时不得把 queryable 传出应用服务边界。

### 13.5 事务

- 事务边界由 Application Service 或 `IUnitOfWork` / Endpoint `Transactional()` 控制。
- 禁止在 Repository 内部随意开启独立事务。
- 事务内不得调用外部 HTTP 或其它不可靠远程 I/O。
- 业务数据与待发送集成事件必须走 Outbox（<c>IOutbox.EnqueueAsync</c>），与业务写同一工作单元；禁止事务内 HTTP / MQ。
- 同模块必须立刻成功的后续写（如公告→收件箱）仍可用 <c>IEventPublisher.PublishAsync</c>。
- 长事务必须拆分；批量操作必须评估锁范围。

### 13.6 批量写入

大批量插入不得逐条 `Insert`。推荐批次大小与等待时间经压测确定（经验起点：每批 1000～5000）。

使用 BulkCopy / 批量 API 前必须验证：字段顺序与映射、数据类型、空值、驱动兼容性、失败重试与隔离、重复数据幂等策略。

### 13.7 多租户

- 租户业务表应具备 `TenantId`。
- 必须配置全局过滤器或统一仓储过滤（目标态）；过渡期手写 `WhereIF` 必须注释（§3.1.3）。
- 后台任务执行时必须经 <c>ITenantScope.RunAsync(tenantId, ...)</c> 设置租户；Quartz 任务参数 JSON 含 <c>tenantId</c> 时框架会自动套作用域。
- Outbox Dispatcher 按行上的 <c>TenantId</c> 进入作用域后再投递。
- 超级管理员跨租户查询必须走专用接口并审计。
- **禁止**依赖前端传入的 `TenantId` 决定最终租户（以登录上下文为准）。
- **登录不传租户**：按账号查用户，`TenantId` 取自 `SysUser.TenantId` 写入 JWT；一账号仅属一个租户；`Account` 全局唯一。
- **超级管理员例外**：`AccountType = SuperAdmin` 跳过租户状态校验，菜单/按钮不过租户启用上限。
- **菜单模型（Id 隔离）**：
  - `SysMenu` 为全局目录；`IsPlatform = true` 的平台专属菜单（系统管理整棵子树）不可纳入租户启用集。
  - 默认可分租户菜单：工作台、个人空间、基础管理（用户/角色/机构/岗位/通知公告）。
  - `SysTenantMenu` 表示租户启用上限；角色 `SysRoleMenu` 必须为其子集；新建租户默认只启用 `!IsPlatform` 菜单。
  - 普通用户有效权限 = 角色菜单 ∩ 租户启用菜单。
- **独立库（`TenantType.Db`）**：`DbConfigId` 必须属于启动连接配置且不得为 `master`；开通状态见 `ProvisionStatus`；管理员账号仍落主库作为账号路由，业务库由 `ITenantDatabaseProvisioner` 建库/InitTables；连接解析见 `ITenantConnectionResolver`。

### 13.8 CodeFirst、建表与迁移

- **生产环境禁止**应用启动时自动修改表结构（`EnableInitTable` / 自动迁移仅限开发）。
- 表结构变更必须通过版本化迁移脚本。
- 删除列、改类型和大表索引必须提供回滚或兼容方案。
- 先发布兼容代码，再迁移数据，最后移除旧字段。
- 禁止直接修改已上线历史迁移文件。

#### 字段中文备注（必须）

- 优先用实体 + SqlSugar 生成/同步表结构：`[SugarTable("xxx", "中文表说明")]`，每个字段 **`[SugarColumn(ColumnDescription = "中文备注")]` 必填**（等价于字段注释）。
- 手写建表 / 改表 SQL 时：**表与每个字段都必须有中文备注**。
- 本仓库默认库为 **PostgreSQL**，使用 `COMMENT ON`；若环境为 SQL Server，使用扩展属性 `sp_addextendedproperty`。
- 字段命名、类型、可空性与同模块既有实体保持一致：主键雪花 `bigint`（`long`）；金额 / 数量优先 `decimal(18,4)`；状态字段遵循 §2.4。

```csharp
/// <summary>
/// 系统用户。
/// </summary>
[SugarTable("sys_user", "系统用户")]
public class SysUser : BaseEntity
{
    /// <summary>
    /// 直属机构 Id；关联 <see cref="SysOrg.Id"/>。
    /// </summary>
    [SugarColumn(ColumnDescription = "直属机构Id")]
    public long OrgId { get; set; }
}
```

```sql
-- PostgreSQL：表与字段中文备注
CREATE TABLE sys_demo (
  id BIGINT NOT NULL PRIMARY KEY,
  status INT NOT NULL DEFAULT 0
);
COMMENT ON TABLE sys_demo IS '演示表';
COMMENT ON COLUMN sys_demo.status IS '状态：0待开工 1进行中 2已完工';
```

```sql
-- SQL Server（若使用）：扩展属性备注
CREATE TABLE [MfgDemo] (
  [Id] BIGINT NOT NULL PRIMARY KEY,
  [Status] INT NOT NULL DEFAULT 0
);
EXEC sp_addextendedproperty 'MS_Description', N'演示表', 'SCHEMA','dbo','TABLE','MfgDemo';
EXEC sp_addextendedproperty 'MS_Description', N'状态：0待开工 1进行中 2已完工',
  'SCHEMA','dbo','TABLE','MfgDemo','COLUMN','Status';
```

### 13.9 数据访问与接口效率（必须）

#### 后端

见 §13.3：联表 / 投影 / 聚合 / `Contains` 批量查；禁止 N+1 与循环单查。  
接口设计：能一次返回主表+关联+汇总的不要拆成多次往返。

#### 前端调用

- **严禁在循环里逐条调接口**（`for` / `map` 里 `await api.xxx()`）组装列表或补关联字段；关联数据由后端一个接口 Join 带回。
- 列表、看板、下拉一次性拉取；确需按需查询时用**批量接口**（传 id/code 数组一次查）。
- composable 编排多个**相互独立**的接口时，用 `Promise.all` 并发，不无谓串行等待。

```ts
// ❌
for (const id of ids) {
  const detail = await api.getById(id)
}

// ✅ 后端批量接口
const list = await api.getByIds(ids)

// ✅ 无关请求并发
const [users, orgs] = await Promise.all([api.pageUsers(q), api.getOrgTree()])
```

## 14. 前端规范

### 14.1 目录：`pages` 与 `modules`

| 目录 | 放什么 | 示例 |
|---|---|---|
| `frontend/src/pages/` | **仅公共壳页面** | `login/`、`exception/` |
| `frontend/src/modules/` | **全部业务域** | `home/`、`system/`、`mfg/`、`dev/` |
| `frontend/src/shared/` | 项目级通用能力 | `components/`、`utils/`、`http/`、`access/` |
| `frontend/src/store/` | **仅全局壳状态** | `user` / `permission` / `theme` / `tabs` |
| `frontend/src/router/` | 路由基础设施 | 守卫、菜单适配、组件白名单 |

菜单 `component` 推荐：`modules/system/views/user/index`。路由兼容历史写法：`modules/system/user/index`、`system/user/index`（自动尝试 `modules/` 前缀与插入 `views/`）。

#### 域目录骨架

```text
modules/<域>/
  api/                 # 本域接口定义（与后端功能 1:1）
  permissions/         # 本域权限码常量表（有则建）
  routes/              # 可选：本域本地异步路由
  stores/              # 可选：仅本域状态（禁止搬登录/主题等壳状态）
  views/               # 功能页面（必须）
    <功能>/
      ...
  index.ts             # 可选：域入口导出
```

- `modules/<域>/`（如 `system/`、`mfg/`）是业务域分组：域根**只允许**上表横切目录 + `views/`，禁止在域根直接堆功能页或跨功能 `components/`。
- 跨功能复用 UI（如标准 CRUD 页）放 `shared/components/`（如 `axis-crud`）。
- 权限判断服务仍在 `shared/access`；权限**码表**放对应域 `permissions/`（如 `modules/system/permissions/codes.ts`）。

#### 单功能模块骨架（渐进）

```text
modules/<域>/views/<功能>/
  index.vue                 # 必须：薄入口（组装 + 绑定，禁止堆业务 UI）
  components/               # 有独立子页面时必须：弹窗、抽屉、Tab、侧栏等
  composables/              # 按需：有状态编排、调 API
  styles/                   # 必须：页面与子组件样式统一放此
  utils/                    # 按需：仅本功能独有的纯函数
  mappers/                  # 可选：复杂页 DTO→视图模型（小页面可不建）
  mocks/                    # 可选：未接 API 时的占位数据
```

单功能域（如工作台）可将页面直接放在 `views/` 根下：`modules/home/views/index.vue` + `components/` 等。

| 目录 | 规则 |
|---|---|
| `components/` | **独立子页面必须拆出**：`*FormDialog`、`*DetailDrawer`、面板/Tab 等；`index.vue` 仅 `import` 后组装。禁止把抽屉/弹窗大块模板写在 `index.vue`。命名：`XxxFormDialog.vue` / `XxxDetailDrawer.vue`（参考 `role/components/`）。 |
| `styles/` | **每个功能模块都建**；`index.vue` 与 `components/*` 的样式**一律**放 `styles/`（如 `styles/index.scss`、`styles/detail-drawer.scss`），组件内 `<style>` 只写 `@use '../styles/xxx.scss';`，禁止在 `.vue` 里堆业务 CSS。禁止 `@import`。 |
| `utils/` | **仅本功能独有**逻辑；通用能力进 `shared/utils`（见下） |
| `mappers/` / `mocks/` | 小页面可不建；复杂 Tab/未接 API 时再建 |
| `composables/` | `ref`/`watch`/API 编排；禁止塞纯格式化与大段常量 |

#### `shared/utils` 与第三方库（优先）

- 跨页面可复用的纯工具放 `frontend/src/shared/utils/`（如 `date.ts`、`message.ts`、`color.ts`、`sm-crypto.ts`）。
- **禁止**在各业务 `modules/**/utils` 复制一份「通用时间/金额/深拷贝」。
- 时间、货币、复杂工具**优先成熟第三方**，不要手写轮子：
  - 日期时间：`dayjs`（已接入，封装见 `shared/utils/date.ts`：`formatLocalDate` / `formatLocalDateTime` / `formatRelativeTime`，并 re-export `dayjs`）
  - 通用集合/对象：优先 `lodash-es`（已依赖）或按需引入
  - 其它能力先查 `shared/utils` 与现有依赖，再考虑自研
- 模块 `utils/` 只保留领域特有逻辑（如某业务树解析、本页状态文案常量）。

#### 业务页面对齐（其它）

- `modules/<域>/api/<功能>.ts` 与后端模块 1:1（如 `modules/system/api/user.ts`）。
- `index.vue` 只做组装；重逻辑进 `composables/`；独立子页面进 `components/`，并由 `index.vue` 引入。
- 标准 CRUD 列表页优先复用 `shared/components/axis-crud`（`AxisCrudPage`）。
- 列表与表单中编码、名称成对出现时：编码在前、名称在后。
- 权限码只引用本域 `permissions`（或经其 `index` 导出）；下拉走字典；接口效率遵守 §13.9；弹窗/抽屉遵守 §14.4。

### 14.2 前端注释规范

与后端 §3 不同：前端**不使用** JSDoc（`/** */`），以块分隔 + `//` 单行说明为主。

#### 区块分隔

组件 `<script>` 内使用**块注释**划分逻辑区块：

```ts
/* ============ 区块名称 ============ */
```

- 分隔注释**上方空一行、下方空一行**。
- 不使用编号，不使用多行式（如 `━━━` 三行式或 `// ------` 线）。
- 推荐区块划分（按需裁剪）：

```ts
/* ============ 状态 & 引用 ============ */

/* ============ 常量 ============ */

/* ============ 工具函数 ============ */

/* ============ 统计聚合 ============ */

/* ============ 视图模型 ============ */

/* ============ 列表排序 & 筛选 ============ */

/* ============ 交互操作 ============ */

/* ============ 对外暴露 ============ */
```

#### 函数 / 变量注释

- 使用 `//` 单行注释，**禁止** JSDoc 风格（`/** */`）：

```ts
// 安全转数字，null/undefined/NaN → 0
const toNumber = (value: unknown): number => Number(value ?? 0) || 0

// 点击记录卡片 → 打开报工详情抽屉
const openReportDetail = (row: ReportRow) => {
  // ...
}
```

#### 通用要求

- 文件头组件说明可选；**业务逻辑、非显而易见处**用中文注释。
- 注释写完整句，说明「做什么、为什么」，避免 `// fix`、`// todo` 无说明。
- 临时待办若必须保留：`// TODO(AXIS-xxx, yyyy-MM-dd): 说明与移除条件`（与后端 TODO 精神一致）。
- `import` 分组清晰（Vue → 第三方 → 项目内 `@/` → 本模块相对路径），组间空一行。

### 14.3 前端代码排版

#### 空行规则

- 区块分隔符前后各空一行。
- **同区块内**相邻的变量/函数之间空一行（逻辑紧密的可不空）。
- 函数体内部逻辑步骤之间可空一行增强可读性，但**禁止连续两个空行**。
- `<template>`、`<script>`、`<style>` 标签之间空一行。
- **`<template>` 必须单根节点**：页面主体与 `FormDialog` / `DetailDrawer` 一并包在同一根容器内（参考 `user/index.vue`）。多根在 keep-alive、过渡动画、页面高度继承下易出问题；Vue 3 Fragment 虽语法合法，业务页禁止使用。

#### 缩进

- 统一 **2 空格**缩进（`.vue`、`.ts`、`.scss`）。
- `<template>` 内 HTML 属性过多时换行对齐，每个属性独占一行。

#### 语句风格

- 一行一语句，禁止一行挤多条。
- 字符串统一用**单引号**（模板字符串除外）。
- 行尾分号：与项目现有风格一致（当前 Web 工程**有分号**则保持有分号）。
- 箭头函数体为单表达式时可省略 `{}`，多行时必须加 `{}`。

#### computed / watch 排版

```ts
// 短表达式：单行
const issueQty = computed(() => recordSummary.value.ngQty + recordSummary.value.scrapQty);

// 多行：括号内缩进
const filteredRecords = computed(() => {
  const keyword = searchKeyword.value.trim().toLowerCase();
  return sortedRecords.value.filter((row) => {
    // ...
  });
});
```

#### 禁止

- 禁止多余尾随空格。
- 禁止连续两个及以上空行。
- 禁止在 `=`、`:`、`=>` 周围缺少空格。
- 禁止大段注释掉的代码提交（确认废弃则删除）。

### 14.4 统一使用公共弹窗 / 抽屉（必须）

本仓库 UI 为 **Naive UI**。业务页禁止直接手写 `n-modal` / `NModal`、`n-drawer` / `NDrawer`（以及 Element 的 `el-dialog` / `el-drawer`）。  
表单弹窗、详情抽屉统一走 `frontend/src/shared/components` 下公共组件；能力不足时**优先扩展公共组件**（props / 插槽），不要在业务页另起一套。

组件经 `unplugin-vue-components` 扫描 `src/shared/components` 自动注册（见 `frontend/build/vite/plugins.ts`），模板中可直接使用 `FormDialog` / `DetailDrawer`；也可显式：

```ts
import { FormDialog } from '@/shared/components/form-dialog'
import { DetailDrawer, type DetailField } from '@/shared/components/detail-drawer'
```

#### 路径与组件对照（以仓库现状为准）

| 用途 | 实际路径 | 导出 / 全局名 | 底层实现 |
|---|---|---|---|
| 表单 / 确认弹窗 | `frontend/src/shared/components/form-dialog/index.vue` | `FormDialog` | 封装 `n-modal`（preset=card） |
| 详情抽屉 | `frontend/src/shared/components/detail-drawer/index.vue` | `DetailDrawer` | 封装 `n-drawer` + `n-drawer-content` |
| 详情字段网格 | `.../detail-drawer/detail-field-grid.vue` | `DetailFieldGrid` | 供抽屉内部使用，业务一般不直接用 |
| 表单字段（可选搭配） | `frontend/src/shared/components/axis-form/` | `AxisForm` | 与 FormDialog 搭配做表单区 |

> 说明：目录名为 **`detail-drawer`**（kebab-case），不是 `detailDrawer`。勿与其它项目里的 Element Plus 路径混用。

#### FormDialog（弹框）

**绑定：** `v-model`（`modelValue` / `update:modelValue`）。

常用 props（完整见 `form-dialog/types.ts`）：

| Prop | 说明 |
|---|---|
| `title` / `subtitle` | 标题与副标题 |
| `icon` | Iconify 名（string）或 Vue 组件 |
| `icon-theme` | `primary` / `success` / `warning` / `error` / `info` |
| `status-text` / `status-type` | 标题旁状态标签 |
| `width` | 默认 `700` |
| `loading` | 内容区 Spin |
| `confirm-loading` / `confirm-disabled` | 确定按钮状态 |
| `show-cancel` / `show-confirm` / `show-footer` | 底部按钮显隐 |
| `cancel-text` / `confirm-text` | 按钮文案 |
| `destroy-on-close` / `mask-closable` / `close-on-esc` / `draggable` | 行为开关 |

插槽：`default`、`header-extra`、`footer`（作用域提供 `close` / `cancel` / `confirm`）。  
事件：`confirm`、`cancel`、`close`、`afterLeave`。  
暴露：`open()` / `close()`。

**约定：**

- `@confirm` **不会自动关闭**；业务提交成功后再把 `v-model` 设为 `false`，避免保存失败弹窗已关。
- 只读提示：`:show-cancel="false"` + `confirm-text="知道了"`，`@confirm` 里 `visible = false`。
- 表单弹窗：`@confirm` 触发提交，`:confirm-loading` 绑提交中状态。

```vue
<script setup lang="ts">
  import { ref } from 'vue'
  import { FormDialog } from '@/shared/components/form-dialog'

  const visible = ref(false)
  const submitting = ref(false)

  async function submit() {
    submitting.value = true
    try {
      // await api...
      visible.value = false
    } finally {
      submitting.value = false
    }
  }
</script>

<template>
  <FormDialog
    v-model="visible"
    title="新增用户"
    subtitle="填写用户的基本信息"
    icon="ant-design:user-add-outlined"
    :confirm-loading="submitting"
    @confirm="submit"
  >
    <!-- 表单内容：可用 AxisForm 或 n-form -->
  </FormDialog>
</template>
```

#### DetailDrawer（详情抽屉）

**绑定：** `v-model:show`（注意是 **`show`**，不是 `visible`）。

常用 props（完整见 `detail-drawer/types.ts`）：

| Prop | 说明 |
|---|---|
| `title` / `subtitle` | 标题与副标题 |
| `icon` | Iconify 图标名，默认 `ant-design:file-text-outlined` |
| `icon-theme` / `status-text` / `status-type` | 头部图标主题与状态标签 |
| `width` | 默认 `760` |
| `loading` | 内容 Spin |
| `fields` | `DetailField[]` 基本信息区 |
| `blocks` | `DetailBlock[]` 多分组信息 |
| `section-title` | 基本信息区标题，默认「基本信息」 |
| `columns` / `label-width` | 字段网格列数与标签宽 |
| `show-footer` / `close-text` | 底部关闭区 |

`DetailField` 要点：

- `type: 'text' | 'code' | 'tag' | 'image'` —— 编码/单号类用 **`type: 'code'`**（不是 `isCode`）。
- `fullRow: true` —— 长字段（备注、名称）独占整行。
- `tagType` —— `type: 'tag'` 时的主题。
- `formatter` —— 自定义展示。

插槽：`default`（自定义主体，等价于扩展内容区）、`header-extra`、`field`（按 `field.key` 定制单字段）、`footer`。  
**当前没有** `stats`、`#extra`、`#header-actions` 命名；统计条等放 `default` 插槽或扩展公共组件新增 props。

```vue
<script setup lang="ts">
  import { ref } from 'vue'
  import { DetailDrawer, type DetailField } from '@/shared/components/detail-drawer'

  const visible = ref(false)
  const fields: DetailField[] = [
    { key: 'account', label: '账号', value: 'admin', type: 'code' },
    { key: 'status', label: '状态', value: '启用', type: 'tag', tagType: 'success' },
```

#### 与常见「其它项目写法」差异（避免照抄错 API）

| 其它项目常见写法 | Axis 现状（必须按此） |
|---|---|
| `el-dialog` / `el-drawer` | 禁止；用 `FormDialog` / `DetailDrawer`（底层 Naive） |
| `detailDrawer/` 驼峰目录 | `detail-drawer/` |
| `v-model:visible` | FormDialog：`v-model`；DetailDrawer：`v-model:show` |
| `desc-fields` / `isCode` | `fields` / `type: 'code'` |
| `header-icon="ele-Tickets"` | `icon="ant-design:..."`（Iconify） |
| `stats`、`#extra` | 无此 API；用 `fields`/`blocks` + 默认插槽，或扩展组件 |
| `common-card` 作弹窗分区 | 本仓库无该全局组件；用抽屉 `blocks` 或自行分区 |

公共组件目录内封装 `n-modal` / `n-drawer` **允许**；仅禁止业务 `pages/`、`modules/` 直接使用。

### 14.5 主题圆角与样式 Token（必须）

布局设置中的「圆角」会写入 CSS 变量 `--axis-border-radius`（见 `use-theme` / `theme-variables.scss`），并同步到 Naive UI 的 `borderRadius`。

**必须：**

- 卡片、分区容器、详情字段块、输入触发器、面板等**常规圆角**使用：

```scss
border-radius: var(--axis-border-radius, 6px);
```

- 禁止在业务页或公共组件里写死 `4px` / `8px` / `10px` / `12px` / `14px` 等「看起来差不多」的圆角，导致与主题设置脱节。

**允许例外（不跟主题圆角）：**

| 场景 | 写法 | 说明 |
|---|---|---|
| 胶囊标签 / 状态 pill | `border-radius: 999px` 或组件 `round` | 语义是全圆角，不是卡片圆角 |
| 圆形头像 / 圆点指示 | `50%` / `999px` | 几何形状固定 |
| 标题左侧竖条 tip | `999px`（细条） | 装饰条，非容器 |

**相关变量（优先用现有 Token，勿另起一套）：**

| 变量 | 含义 |
|---|---|
| `--axis-border-radius` | 主题圆角（布局设置可改） |
| `--axis-primary-color` 等 | 主题色与文本/边框/背景系变量 |

新增 UI 时先查 `frontend/src/assets/styles/theme-variables.scss` 与 `layouts/composables/use-theme.ts`，与主题配置对齐后再写样式。

### 14.6 统一滚动条：`n-scrollbar`（必须）

本仓库 UI 为 **Naive UI**。凡需要**自定义滚动区域**（侧栏树、面板列表、抽屉内长内容、布局子菜单等），统一使用 `n-scrollbar` / `NScrollbar`，禁止依赖浏览器原生滚动条样式。

**必须：**

- 可滚动容器用 `n-scrollbar` 包裹内容；外层负责定高 / `flex: 1; min-height: 0`，由 `n-scrollbar` 承担滚动。
- 业务页、布局、公共组件新增滚动区时，默认采用 `n-scrollbar`（参考 `modules/system/views/menu/components/MenuTreePanel.vue`、`layouts/components/layout-sider`）。

```vue
<!-- ✅ 推荐 -->
<div class="panel__body">
  <n-scrollbar class="panel__scroll">
    <!-- 长内容 -->
  </n-scrollbar>
</div>
```

```scss
.panel__body {
  flex: 1;
  min-height: 0;
  overflow: hidden; // 仅裁剪，不滚动
}

.panel__scroll {
  height: 100%;
}
```

**禁止：**

- 为「做出滚动效果」在业务容器上写 `overflow: auto` / `overflow: scroll` / `overflow-y: auto` 等，依赖系统原生滚动条。
- 在已用 `n-scrollbar` 的区域再叠一层原生 `overflow: auto`（双重滚动）。

**允许例外：**

| 场景 | 说明 |
|---|---|
| `overflow: hidden` | 布局裁剪、配合 flex 高度链，**不是**滚动方案 |
| Naive 组件内部滚动 | 如 `n-data-table`（含 `flexHeight`）、`n-select` 下拉等，勿强行外包一层破坏组件行为 |
| 第三方 / 代码高亮等 | 组件自带滚动且无法替换时，可保留；新写业务区仍用 `n-scrollbar` |

存量页面若仍用原生 `overflow: auto`，改到该区域时一并改为 `n-scrollbar`，不必单独开大重构。
