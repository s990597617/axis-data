# 云枢 Axis · 轻量模块脚手架

> 一期：模板复制落盘合规 CRUD 骨架。  
> 二期①：读表 / 实体列 → 真实业务字段。  
> 二期②：权限自动合并。  
> 二期③：菜单种子类。  
> 二期④：**管理端网页生成**（与 CLI 共用 `tools/Axis.Scaffold.Core` 引擎）。  
> 目录与拆分对齐 [业务开发规范.md](./业务开发规范.md) §2、§14.1。

---

## 管理端网页（推荐）

1. 配置 `src/Axis.Host.Api/Config/08-CodeGen.json`：`CodeGen:Enabled=true`（生产保持 `false`；`AllowInProduction` 默认 `false`）。
2. 启动 API + 前端，用超级管理员登录。
3. 菜单：**系统管理 → 代码生成**（`/system/code-gen`）。
4. 填写模块名 / 中文名 / 域，可选「数据库表」或「Domain 实体」作字段来源 → **预览代码**（左侧文件列表 + 右侧全文）→ **生成落盘**。
5. 生成后执行 `dotnet build Axis.Net.sln`，前端按需类型检查；角色菜单若未自动授权，在菜单管理分配。

API：`GET /sys/code-gen/status|tables|entities`，`POST /sys/code-gen/preview|generate`。  
预览/生成结果中每个 `actions[]` 含 `content`（将写入的完整源码；`SKIP` 为空）。  
权限：`sys:codeGen:query|preview|generate`。

## CLI 用法

在仓库任意子目录执行（工具会向上查找 `Axis.Net.sln`）：

```bash
# 默认五字段（Name/Code/Status/OrderNo/Remark）
dotnet run --project tools/Axis.Scaffold -- new module Product \
  --cn 产品 --area Demo --route-key product

# 从已有实体反射字段（需先编译 Domain）
dotnet build src/Axis.Domain
dotnet run --project tools/Axis.Scaffold -- new module Pos \
  --cn 岗位 --area Demo --from-entity SysPos --force

# 从数据库表列生成字段（读 08-Db.json 主库连接）
dotnet run --project tools/Axis.Scaffold -- new module Product \
  --cn 产品 --area Demo --from-table demo_product --force
```

### 常用参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `module` | PascalCase 模块名 | 必填 |
| `--cn` | 中文名 | 必填 |
| `--area` | 业务域（`Demo` / `Biz` / `System`…） | `Demo` |
| `--route-key` | URL / 权限段 | 由模块名 kebab 推导 |
| `--entity` | 实体名 | `Sys{Module}`；有 `--from-entity` 时用其实体名 |
| `--table` | 表名 | `{sys\|area}_{route_key}` |
| `--from-table` | 从 DB 表列生成字段（与 `--from-entity` 互斥） | — |
| `--from-entity` | 从 Domain 实体反射字段（与 `--from-table` 互斥） | — |
| `--dry-run` | 只列路径不落盘 | off |
| `--force` | 覆盖已存在文件 | off |
| `--backend-only` / `--frontend-only` | 单侧生成 | 双侧 |
| `--no-menu` | 不生成菜单种子类 | off |

### 字段规则

- 跳过基类 / 框架列：`Id`、审计字段、`Deleted`、`Version`、`TenantId`（实体仍固定挂 `ITenantId` + `TenantId`）。
- 列名 `Status` 且为整型 → `StatusEnum`；前端状态列 / 单选自动带上。
- 存在 `Code` → 生成租户内唯一校验。
- 关键字搜索优先匹配 `Name`/`Code`，否则取第一个字符串列。
- 无 `--from-*` 时仍用默认五字段。

### 安装为本地 / 全局 tool（可选）

```bash
dotnet pack tools/Axis.Scaffold -c Release -o ./.local-tools
dotnet tool install Axis.Scaffold --global --add-source ./.local-tools
# 之后：
axis new module Product --cn 产品 --area Demo --from-entity SysProduct
```

卸载：`dotnet tool uninstall Axis.Scaffold -g`。

## 生成什么

**后端**

- `src/Axis.Domain/{Area}/{Entity}.cs`
- `src/Axis.Application/{Area}/{Module}/`：`Dto/`、`Validators/`、`I*AppService`、`*AppService`
- `src/Axis.Host.Api/{Area}Endpoints/{Module}/`：Page / Create / Update / Delete（一文件一类）

**前端**

- `frontend/src/modules/{area}/api/{module}.ts`
- `frontend/src/modules/{area}/views/{module}/`：`index.vue` + `composables` + `styles`（`AxisCrudPage`）

**权限（二期②：自动合并）**

| 场景 | 行为 |
|---|---|
| `--area` ≠ `System` 且 `{Area}PermissionCodes.cs` 不存在 | 生成完整权限根类（含本模块） |
| 权限根类已存在（含 System） | **自动 MERGE** 嵌套模块类；已存在同名模块时需 `--force` |
| 前端 `codes.ts` 不存在 | 生成完整码表 |
| 前端 `codes.ts` 已存在 | **自动 MERGE** 权限键；已存在同名键时需 `--force` |

**菜单（二期③）**

- 默认生成 `src/Axis.Domain/System/Seeds/Generated/{Area}_{Module}MenuSeed.cs`
- 含域目录（非 System）、页面菜单、查询/新增/编辑/删除按钮
- Id 按 Area/Module 稳定哈希，落在 `1000_0006_8xxx` 段，不改 `SysMenuSeed`
- **仅当** `EnableInitSeed=true` 时写入数据库；生产请关闭该开关
- 角色菜单授权仍须在「菜单管理」中分配（`SysRoleMenuSeed` 只绑定内置 `SysMenuSeed`）
- `--no-menu` 可跳过

**不会自动改**

- `ApiGroupEnum` / `SysRoleMenuSeed`
- 解决方案 / CI 工程文件

## 与 CodeGen 配置的关系

[`08-CodeGen.json`](../src/Axis.Host.Api/Config/08-CodeGen.json) / [`AxisCodeGenOptions`](../src/Axis.Infrastructure/Options/AxisCodeGenOptions.cs)：

| 键 | 说明 |
|---|---|
| `Enabled` | 管理端 API 总开关 |
| `AllowInProduction` | 生产是否允许（默认 false） |
| `RepoRootPath` | 可选，显式指定含 `Axis.Net.sln` 的仓库根 |

引擎在 `tools/Axis.Scaffold.Core`；CLI（`tools/Axis.Scaffold`）与网页共用，网页读表优先走注入的 `ISqlSugarClient`。
